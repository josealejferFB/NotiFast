# Área de Estudio (Study Hub) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir la sección principal «Área de Estudio» (`Screen.StudyHub`) en NotiFast con un Gestor Offline-First de Documentos Académicos (`.pdf` y `.docx` con vista previa nativa zero-bloat, duplicación, vínculo por materia y compartición) y un Diseñador Inteligente de Plantillas de Portadas Académicas (`APA 7`, `IEEE`, `Institucional`) con exportación `.docx` local y creación directa en Google Docs vía Drive API v3 (`drive.file`).

**Architecture:** Clean Architecture estricta + MVI (un único `StateFlow<StudyHubUiState>` y `onEvent(StudyHubEvent)` en `StudyHubViewModel`). Persistencia local en Room Database `v6` (`study_documents` y `cover_drafts`) con archivos físicos en el sandbox `context.filesDir/study_docs/` expuestos vía `FileProvider`. Previsualización de PDF mediante `android.graphics.pdf.PdfRenderer` sincronizado con `Mutex` y previsualización/generación de `.docx` mediante motores ligeros OpenXML (`ZipInputStream`/`ZipOutputStream` + `javax.xml.parsers.DocumentBuilderFactory` con `0 KB` de dependencias externas).

**Tech Stack:** Kotlin `2.0.21`, Jetpack Compose (Material 3), Room `2.7.2` (`v5 ➔ v6`), Hilt `2.59`, OkHttp `4.12.0`, Google Identity `AuthorizationClient` (`drive.file`), JUnit 4, MockK, Coroutines Test, Robolectric `4.13`, MockWebServer.

**Spec:** [`docs/superpowers/specs/2026-10-19-study-hub-design.md`](file:///home/p0xd/Documentos/proyectos/NotiFast/docs/superpowers/specs/2026-10-19-study-hub-design.md)

## Global Constraints

- **Cero dependencias pesadas en APK:** Prohibido añadir Apache POI o motores PDF nativos de terceros; usar exclusivamente `PdfRenderer` de Android, `java.util.zip.*` y `javax.xml.parsers.*` (incluidos en JDK/Android runtime).
- **Límite de tamaño por archivo Composable:** Máximo `~250` líneas por archivo en `presentation/`. Subdividir en sub-componentes dentro de `presentation/feature/studyhub/components/`.
- **MVI Estricto:** Un único `val uiState: StateFlow<StudyHubUiState>` en `StudyHubViewModel` y un único punto de entrada `fun onEvent(event: StudyHubEvent)`.
- **Apego al Sistema de Diseño 3.2 y Átomos:** Usar `MaterialTheme.colorScheme.isDark` (prohibido `isSystemInDarkTheme()`), `NotiFastCard`, `NotiFastButton`, `NotiFastTextField`, `NotiFastDialog`, `NotiFastTopBar`, `NotiFastEmptyState`.
- **Cero Strings Hardcodeados en UI:** Todos los textos de interfaz en `app/src/main/res/values/strings.xml` en español.
- **Manejo de Excepciones:** Cero bloques `catch` vacíos; toda operación de I/O o red debe envolverse en `try/catch` y retornar `Result<T>`.
- **Compatibilidad JVM + Android en XML:** Para el parser OpenXML (`OpenXmlDocxParser`), usar `javax.xml.parsers.DocumentBuilderFactory` en lugar de `android.util.Xml` para que las pruebas unitarias corran en JVM puro en `< 50 ms` sin requerir emulador.

## Review Focus

1. **Archivo `.docx` corrupto o sin `word/document.xml`:** Si el usuario importa o previsualiza un archivo con extensión `.docx` que no es un ZIP válido o carece de `word/document.xml`, `OpenXmlDocxParser.parse(inputStream)` debe capturar la excepción y retornar `Result.failure(InvalidDocumentFormatException)` sin crashear.
2. **Protección contra documentos gigantes (OOM / Zip Bomb):** `OpenXmlDocxParser` debe limitar la lectura de `word/document.xml` a `10 MB` máximo y truncar la salida a `MAX_PREVIEW_BLOCKS = 300` bloques, añadiendo un párrafo informativo final cuando el documento supera ese límite.
3. **Sanitización de nombres de archivo al duplicar o exportar `.docx`:** Si el título contiene caracteres ilegales de sistema de archivos (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`), el archivo físico en `filesDir/study_docs/` usa un UUID seguro (`{uuid}.docx`) mientras Room conserva el `title` original intacto.
4. **Autorización OAuth `drive.file` cuando el token sólo tiene `drive.appdata` o expiró (`401`/`403`):** `GoogleDocsExportRepository` solicita explícitamente `authorizeDriveFile(email)` (scope `https://www.googleapis.com/auth/drive.file`); si Google Play Services requiere consentimiento incremental del usuario, propaga `DriveAuthResult.NeedsResolution(pendingIntent)` al `StudyHubUiState.pendingAuthIntent` para que la UI muestre el diálogo nativo de Google y reintente al aprobarse.
5. **Eliminación física al borrar documento en Room:** Cuando el usuario elimina un `StudyDocument`, `LocalStudyDocumentRepositoryImpl.deleteDocument` debe borrar tanto la fila en `study_documents` como el archivo físico en `filesDir/study_docs/{fileName}` (ignorando silenciosamente si el archivo físico ya no existía).
